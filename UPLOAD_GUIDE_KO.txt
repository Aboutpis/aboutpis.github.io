RC5.8.7.32 운영 저장소 전체 업로드 안내

운영 저장소: https://github.com/Aboutpis/aboutpis.github.io
운영 사이트: https://aboutpis.github.io/
테스트 저장소 Botc-test는 그대로 남겨두세요.

이 ZIP은 업데이트 파일만 있는 것이 아니라 실행에 필요한 전체 파일을 포함합니다.
배경·글꼴·시침 등 테마 파일과 새 시나리오 20개, 토큰 수정까지 포함된 RC32입니다.

[먼저]
ZIP을 전체 압축 해제하세요. ZIP 자체를 GitHub에 업로드하지 않습니다.
기존 저장소의 파일을 전부 삭제할 필요 없습니다. 같은 위치, 같은 이름으로 업로드하면 교체됩니다.

[휴대폰 GitHub에서 올리기]
1. aboutpis.github.io 저장소 맨 위에 아래 10개 파일을 모두 올립니다.
   index.html
   app.js
   config.js
   grimoire.js
   vote.js
   scripts-ko.js
   style.css
   trouble_brewing.json
   sects_and_violets.json
   bad_moon_rising.json

2. theme-assets/village-v30 폴더 구조를 그대로 유지합니다.
   이전에 이 운영 저장소에도 같은 폴더를 만들어 뒀다면 그대로 쓰면 됩니다.
   폴더가 없다면 저장소 맨 위의 Add file → Create new file에서 각각 다음 파일을 만듭니다.
   theme-assets/village-v30/assets/.gitkeep
   theme-assets/village-v30/licenses/.gitkeep
   내용에는 keep을 적고 Commit changes 합니다.

3. GitHub theme-assets → village-v30 → assets 안에서
   압축 푼 assets 안의 파일 83개를 모두 올리고 Commit changes 합니다.
   이미지·SVG·글꼴 파일을 빠짐없이 선택해야 합니다.

4. GitHub theme-assets → village-v30 → licenses 안에서
   압축 푼 licenses 안의 파일 3개를 올리고 Commit changes 합니다.

5. GitHub theme-assets → village-v30 안에서
   theme.css / theme.js / asset-manifest.json 파일 3개를 올립니다.
   assets 안에 넣으면 안 됩니다.

6. 업로드를 모두 마친 뒤 Actions에서 Pages 배포가 성공했는지 확인하고
   https://aboutpis.github.io/ 를 새로고침합니다.
   운영 주소에는 /Botc-test/를 붙이지 않습니다.

[PC에서 올릴 때]
압축을 푼 루트 파일 10개와 theme-assets 폴더를 저장소 루트에 복사/업로드합니다.
라이선스 파일과 폴더 구조를 유지하세요.

[Firebase]
운영 저장소의 기존 config.js를 확인했고, RC32 테스트 앱과 Firebase 설정이 같습니다.
이 묶음에도 운영 저장소의 기존 config.js를 그대로 넣었습니다.
Firebase 보안 규칙을 새로 붙여넣거나 데이터베이스를 지울 필요 없습니다.
두 사이트는 같은 Firebase 프로젝트/데이터베이스를 사용하므로 방 데이터가 공유됩니다.
테스트와 운영의 데이터까지 완전히 분리하려면 별도 Firebase 설정이 필요합니다.
이번 묶음은 기존 연결을 그대로 유지합니다.

[마지막 확인]
- RC5.8.7.32 버전
- 배경 표시
- 한글 틴시빌 10개/커스텀 10개 접기 목록
- 자동/수동/뽑기 선택 표시
- 새 시나리오 역할 토큰과 스크립트 설명
- 사회자와 참가자 각각 운영 주소로 접속해 방 입장 및 질문/투표 확인

게임 로직은 앞서 테스트한 RC32와 같습니다. 이번 작업은 운영 저장소용 전체 파일 포장입니다.
운영 저장소에 직접 업로드하거나 배포한 상태는 아닙니다.
